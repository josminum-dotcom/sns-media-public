# sns-media-public

**게시 직전의 자산만 잠시 머무는 곳이다. 코드는 없다.**

Meta 는 이미지·영상을 **직접 가져간다** — 바이트를 올려주는 게 아니라 URL 을 주면
자기들이 받아온다. `sns-media-agent` 의 `content/<id>/` 는 로컬 경로라 그대로는
API 에 못 넘긴다. 그래서 발행 직전에 여기로 push 하고, URL 로 넘긴다.

## 규칙

- **2차 승인(예약) 전에는 한 바이트도 올리지 않는다.** 이게 뚫리면 사용자가 반려한
  콘텐츠가 인터넷에 남는다 — 헌장 §7 을 우회하는 경로가 된다
- push 는 발행 스크립트가 API 를 부르기 **직전**에 한다. 예약 등록 시점이 아니다
- 발행에 성공하면 파일을 지우는 커밋을 한 번 더 한다
- **커밋 메시지에 캡션·해시태그를 넣지 않는다.** 파일명과 slug 까지다 — 아직 공개되지
  않은 문구가 커밋 로그로 먼저 나가면 안 된다
- 여기 오는 자산은 전부 직접 만든 것이다(`rights_basis='generated'`). 타인 저작물·
  얼굴은 상위 저장소의 `rights_gate` 가 이 앞에서 막는다

## 왜 공개인가

여기 올라간 파일은 **몇 초 뒤 인스타그램에 공개 게시된다.** 공개 시점이 몇 초
앞당겨질 뿐 노출 대상이 달라지지 않는다. 지켜야 할 선은 "공개하지 않는다"가 아니라
**"승인 전에는 올리지 않는다"** 다.

천장 하나: **git 히스토리에는 남는다.** 삭제 커밋은 최신 트리에서만 지운다.
히스토리 재작성은 하지 않는다 — 어차피 공개된 게시물의 자산이고, force push 를
일상 경로에 넣으면 훨씬 비싼 사고가 생긴다.

## URL 규칙

```
https://raw.githubusercontent.com/josminum-dotcom/sns-media-public/main/<slug>/<파일명>
```

규칙으로 결정되므로 DB 에 URL 컬럼을 두지 않는다.

설계: `sns-media-agent/docs/specs/phase8-approval-publish.md` §6-D
